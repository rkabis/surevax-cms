## "Use existing schema" verdict (no new tables)

The v2 schema is a superset of AppSheet. Every legacy concept has a home in an
existing table/column:

| Legacy concept                             | v2 home (already exists)                                                                                                   |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| `p_Categorization` 1/2/3                   | `encounters.triage_category`                                                                                               |
| `p_OnboardingChannel`, `p_SourceOfConcern` | `patients.onboarding_data.{channel,sourceOfConcern}`                                                                       |
| Health card URL                            | **dropped** (B2); regenerate in v2                                                                                         |
| Biting-animal Day-14 status                | `animal_observation_followups`; `Alive` → `Completed/AliveHealthy` only for a uniquely resolved incident                   |
| Human patient's first ARV date             | regimen/episode anchor candidate plus raw patient migration provenance; never animal vaccination proof                     |
| `FullyPaid` ₱200 discount                  | `transactions.discount_id_type='Other'` + `discount_id_number` + `discount_amount` + `patient_tags(FULLY_PAID_PEP_COURSE)` |
| Senior/PWD                                 | `transactions.discount_id_type` enum (OSCA/PWD)                                                                            |
| QCID/DMCI/BFP/PPSV3                        | `discount_id_type='Other'` + `discount_id_number`                                                                          |
| AyalaMalls (+15%)                          | `service_prices` row w/ `payer_id=PAYER_AYALA_MALLS`                                                                       |
| Cross-format duplicates                    | `patients.merged_into_id` + `patient_tags(POTENTIAL_DUPLICATE)`                                                            |
| ARV-PEP courses                            | `patient_standing_orders` + `clinical_orders.patient_standing_order_id`                                                    |
| Orphan remarks                             | `patients.onboarding_data.legacyNotes`                                                                                     |
| Matched remarks                            | `encounters.clinical_notes.remarks`                                                                                        |
| Partner billing (Hati/Forticare/etc.)      | `transactions.payer_id` + `payments.reconciliation_status`                                                                 |
| Per-physician attribution                  | `transaction_items.performed_by_id`                                                                                        |

**Only genuinely-new infrastructure (optional):** a `legacy_appsheet_id text`
column + partial-unique index on 9 entities (NOT patients) for ON-CONFLICT
re-runnability. Skippable if a one-shot, no-retry cutover is acceptable.

**Seed additions (no DDL):** payer profiles `PAYER_AYALA_MALLS`,
**`PAYER_INTELLICARE`**, **`PAYER_AVEGA`** (the last two HMOs are the dominant
charge accounts — ₱4.46M AR / 917 txns, discovered in round-2 analysis §21); 9
missing branch rows; `tag_definitions` rows `FULLY_PAID_PEP_COURSE`,
`POTENTIAL_DUPLICATE`, `LEGACY_NOTE_NEEDS_CLINICAL_REVIEW`. (Requires touching
`apps/backend/src/shared/db/seed/` — was out of scope for the scaffold; confirm
before editing.)
