# Reference Data and Production Prerequisite Audit — 2026-08-17

> **Scope:** PHI-safe audit of the target schema, current seed/configuration,
> AppSheet source shapes, and migration `LoadPlan`/writer. It intentionally
> contains no source rows, names, emails, free-text notes, credentials, or
> patient identifiers.

## Bottom line

The target has most of the _tables_ needed for the operational foundation, but
the current development seed is not itself a production reference-data import.
It contains a useful 14-branch/roster/catalog/template scaffold, whereas the
live AppSheet sheets must still establish the production mapping and the
operator-approved access configuration.

The safe initial local trial can reuse already-seeded, semantically compatible
reference rows and write only base patient, encounter, observed-administration,
transaction, item and payment facts. It must not create replacement branch,
staff, product, catalog, schedule or cash-drawer records merely because their
legacy IDs differ.

### Historical `surevax_db` dedupe rule

The legacy database's 645 patient candidates split into 399 high-confidence
multi-field matches, 4 single-evidence candidates, 238 ambiguous candidates and
4 unresolved candidates against the current source. Only the 399
multi-evidence matches may be automatically linked as historical corroboration.
The remainder stays as source observations and a named reconciliation queue.
No historical row may replace a current patient, transaction, administration,
schedule or reference record without an explicit event-level decision.

## What to inspect in other `surevax_gsheet_db` copies

Historical copies are valuable only for reference records that differ from the
live freeze. They must be profiled and mapped; they must never overwrite the
live AppSheet source or be unioned blindly.

1. Compare **sheet headers and distinct reference keys only** for `Branch`,
   `Nurse`, `AdminEmails`, `Vaccine`, `Discount` and `ChargeAccounts`.
2. Produce an explicit delta for branch slugs/codes, staff legacy keys, payer
   labels, catalog brands/types/routes/doses and discount labels.
3. Classify each delta as **same canonical record**, **retired historical
   record**, **new target configuration needed**, or **unresolved/withheld**.
4. Use the latest stable live freeze for current operational state. A historical
   copy may support provenance or an old reference alias, but cannot silently
   replace active price, branch, staff-access or schedule configuration.

## Recommended load boundary

```text
Seed / approve target foundation
  tenant + signed branch map + reviewed staff directory + payer map
  + catalog aliases + templates + migration tag definitions
       ↓
Base-facts local trial
  patients + approved legacy-import consent + encounters
  + observed administrations/external facts + transactions/items/payments
       ↓
Withheld until reconstructed or separately approved
  patient schedules + timekeeping + cash sessions + inventory opening + price history
```

This is intentionally stricter than “the table exists”: operational reference
configuration and historical evidence have different owners and different
failure modes.
