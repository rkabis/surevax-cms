## 2026-08-16 nurse-workflow pass

- `/today` is calibrated for the normal branch staffing model (one or two
  nurses, low-volume arrivals): **Care now** precedes **Follow-up**, with two
  lanes in each area instead of four equally competing cockpit columns.
- Scheduled Orders defines **Upcoming** as tomorrow plus the following Manila
  clinic day. Initial-load counts use an em dash/loading state instead of false
  zeroes.
- Administration uses an explicit **brand-only** choice and a bedside
  checkpoint containing patient identity, dose facts, route/site, clinical
  flags, administering clinician, and consent. The final commit remains the
  only action labelled **Confirm & administer**.
- Arrivals no longer defaults to Rabies. Specialty is explicit; a Rabies path
  requires WHO exposure category, progressively discloses optional bite detail,
  captures explicit patient/guardian consent, and keeps Back/Continue visible
  in a sticky footer. The atomic API independently rejects Rabies without a WHO
  category and Category III bundles without an ERIG/HRIG service.
- Direct scheduled-order reads and writes are branch-scoped for every clinical
  branch role; active recalls and actual order quantity are revalidated in the
  server-side inventory deduction transaction.
- Patient identity is consistently MRN + DOB/age. Patient-chart actions are no
  longer duplicated, clinical flags stay visible, and incomplete next-dose data
  fails visibly instead of rendering an ambiguous `due —` banner.

Expansion state persists per browser in `localStorage['sv.navOpenGroups']`; default is Today + Records open, Administration closed. A group containing the active route auto-expands even if the user collapsed it. Session card at bottom (Avatar + name + role + LogOut icon, wrapped in DropdownMenuTrigger). Mobile: Sheet drawer (`side="left"`) with hamburger trigger renders the same three groups.

**Top bar** (redesigned 2026-05-06): slash-separated breadcrumbs (derived from `useLocation()` against `ROUTE_LABELS` map), centered spacer, search button (opens global `CommandDialog` via Cmd+K, shows "Search patients, orders…" placeholder with ⌘K kbd hint), notification bell → `/admin/notifications`, settings gear → `/settings`. Bell + gear render only for admin roles (their targets are admin-gated). Previously: hamburger + breadcrumbs + user dropdown.

**Keyboard shortcuts dialog** (`?` key, also reachable from user dropdown): Shadcn `Dialog` rendering the `SHORTCUTS` registry from `shared/components/shortcuts.ts` grouped by category. The `?` listener ignores keypresses inside inputs/contenteditable elements. Future units can register new shortcuts by appending to the registry.

**Role-based sidebar nav** (`src/shared/components/AppShell.tsx`): three collapsible groups defined as `NAV_GROUPS`:

- **Today** — Dashboard, New Arrival, Scheduled Orders, Encounters, Appointments. Shown to all authenticated users.
- **Records** — Patients, Lab Orders, Adverse Events, Bite Incidents, Transactions, **Group Bills** (billing roles only), Inventory, Services, and Reports. Reports reveals financial tabs only to authorized finance roles and otherwise exposes the branch-scoped unbilled clinical worklist.
- **Administration** (`adminOnly: true`) — Users, Approvals, Attendance, Audit Log, Partner Labs, Payer Profiles, Standing Orders, Claims, Product Recalls, Notifications, **Inv. Transfers** (`/inventory-transfers`, Wave 2.3). Shown only to `TenantAdmin` / `BranchAdmin` roles (`SuperAdmin` legacy alias also accepted).

Stub pages whose backend hasn't shipped (Cold Chain and Settings) are reachable by URL but absent from nav; their pages render the shared `ComingSoon` component (`src/shared/components/ComingSoon.tsx`). Reports is operational at `/reports`, with explicit branch/payer filters, bounded lists, and branch/day CSV generated server-side only after its SHA-256-bound audit event commits. Clinical Orders was previously dropped (2026-05-07) as a duplicate of Scheduled Orders but was re-added as its own page in [#241](https://github.com/njvil/surevax-cms-revamp/pull/241) at `/clinical-orders`; it is now in the **Administration** nav group. The `/standing-orders` route was renamed to `/initiate-protocol` to disambiguate from `/admin/standing-orders` (templates); the old URL redirects.

**Shift tracking** (`src/features/shift/`): `ShiftProvider` wraps `AppShell`. Only `Nurse`, `Cashier`, `Physician` roles (`isStaff = true`) ever trigger the **self** clock-in modal — Admins and Branch sessions are unaffected. Branch sessions clock other people in/out via the kiosk page (`/branch/kiosk`), not the modal. `useActiveShift({ enabled: isStaff })` is disabled for non-staff so `data = undefined`; the modal/banner open conditions must check `isStaff` first (`isStaff && !isLoading && activeShift === null`) to avoid false-positives from `undefined` data. "End Shift" appears in the user dropdown only when `activeShift !== null`. Signing out with an active shift prompts a confirm dialog and auto-clocks-out before logout.

**RequireAdmin guard** (`src/App.tsx`): Wraps all `/admin/*` routes. Non-admin users are redirected to `/dashboard`.

**react-resizable-panels v4 note**: Numeric size props are **pixels**, string props are **percentages**. Always use strings: `defaultSize="30%"`, `minSize="20%"`, `maxSize="50%"`. Using bare numbers (e.g. `maxSize={45}`) caps the panel at 45px. See `src/components/ui/resizable.tsx` for the wrapper.

**Local backend .env**: `apps/backend/.env` is required to run locally — backend falls back to `localhost:5432` without it. The file is gitignored. See CLAUDE.md → "Local development .env" for the required keys and how to regenerate from Railway.

**Shadcn/ui install note**: The `shadcn` CLI cannot find `pnpm` in its PATH when run via `pnpm dlx`. Install Radix peer deps manually with pnpm, then write component files directly. Components live in `src/components/ui/`; `components.json` is present for future CLI use once PATH is resolved.

## Runtime Review Center pattern (PR #616, pending merge)

`/review-center` is a server-owned operational worklist, not a dashboard or a
migration-review UI. It reuses severity stripes, semantic badges, truthful
loading/empty/error states, and `DetailSheet` for the one inline correction.

- Navigation is visible only to `TenantAdmin`, `BranchAdmin`, `Physician`,
  `Nurse`, and `Branch`; the server repeats and enforces the role and concrete
  branch checks.
- Counts remain complete while displayed rows are capped at 200. A successful
  empty result, a filtered empty result, loading, and API failure must remain
  visually distinct.
- Guardian correction shows the exact three fields to be written before the
  confirm action and sends the reviewed `rowVersion`; stale data returns a
  conflict instead of overwriting another actor.
- Loose-end rows deep-link to their existing encounter, transaction,
  scheduled-order, or branch-kiosk owner. The Review Center does not reproduce
  those state transitions.
- A clinical reviewer can see a drawer exception but sees “financial role
  required,” not a drawer write affordance. The branch kiosk resolves a
  prior-day Open drawer and never prompts to open a second one.

Full contract: [`../specs/review-center-phase-1.md`](../specs/review-center-phase-1.md).

## Design Philosophy

1. **Speed over aesthetics** — nurses process patients quickly.
2. **Reduce cognitive load** — high-stress clinical environment.
3. **Desktop-first, keyboard-optimized** — primary access via desktop PC.
4. **Role-specific interfaces** — different views per role.
5. **Minimize clicks** — every click costs time.
6. **Keyboard shortcuts** — power users need fast navigation.

## Keyboard Navigation Rules

**Goal**: **Clinical speed** — lists and forms usable **without** the mouse.

| Input                   | Action                                              |
| ----------------------- | --------------------------------------------------- |
| **↑** / **↓**           | Move selection in lists                             |
| **Enter**               | Select row / submit primary action where applicable |
| **Tab** / **Shift+Tab** | Next / previous focusable field                     |
| **Esc**                 | Close modal / cancel / dismiss overlay              |
| **/**                   | Focus **search** input                              |

### Modifiers & Conflicts

- **Avoid** **Ctrl+letter** (and similar) shortcuts — **conflict** with browser/OS and extensions.
- **Prefer** **Alt/Option** + key, or a **command palette** (**Ctrl+K** / **Cmd+K**) for global actions.
- **Future**: **Sequence** shortcuts (e.g. `g` then `p` = go to patients) — document when implemented.

### Command Palette (Recommended Primary Pattern)

| Aspect         | Spec                                                                          |
| -------------- | ----------------------------------------------------------------------------- |
| **Trigger**    | **Ctrl+K** (Windows/Linux) / **Cmd+K** (macOS)                                |
| **Behavior**   | Opens **searchable** command list with **fuzzy matching**                     |
| **Examples**   | Type `new patient` → Enter; `scheduled orders` → Enter; `transaction` → Enter |
| **Navigation** | **↑↓** to select, **Enter** to execute, **Esc** to dismiss                    |
| **Features**   | Recent commands history, fuzzy search, shortcut hints in tooltips             |
| **Why**        | **Zero browser conflicts**, discoverable, consistent across OS                |

**Power-user sequence shortcuts** (Phase 2+):

| Sequence  | Action                       |
| --------- | ---------------------------- |
| `g` → `p` | Go to **Patients**           |
| `g` → `s` | Go to **Scheduled Orders**   |
| `n` → `p` | **New Patient**              |
| `n` → `t` | **New Transaction**          |
| `?`       | Show **shortcut help** modal |

**Invariant**: Every **interactive** control must be reachable via **Tab**; list **selection** must work with **arrow keys** where lists exist.

## Form Design Rules

- **Single column** layout.
- **Labels above** fields (**not** floating/inside-only).
- **Auto-focus** first field on open.
- **Tab order** = **visual order**.
- **Real-time inline** validation (**Zod** + **React Hook Form**).
- **Primary** button: **blue**, **right-aligned**.
- **Secondary**: **gray**, **left-aligned**.
- **Destructive**: **red**.
- **Mutation UI state (required)**: During **TanStack Query** mutations, submit actions must use `isPending` to **disable** submit/primary action buttons and show a clear loading indicator (spinner or `Saving...`) to prevent double-submissions on slow/unstable connections.

## Accessibility Requirements (WCAG 2.1 AA)

- **Contrast** ≥ **4.5:1** for text.
- **Full keyboard** navigation (see rules above).
- **ARIA** labels on **all** interactive elements (**Shadcn/ui** + Radix patterns).
- **Visible focus** indicators (do not remove outlines without replacement).
- **Focus trap** in **modals** / dialogs.
- **Skip** navigation link(s) to main content.

## Frontend Invariants

7. **Perf**: meet **FCP/TTI/LCP** targets; **route-level** code split and **lazy** heavy UI.
