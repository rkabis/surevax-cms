## Implemented Modules (as of 2026-08-23)

Every module exposes both a **list** (`GET /api/<resource>`) and a **detail** (`GET /api/<resource>/:id`) endpoint. Detail endpoints join related entities so the frontend's detail drawer can render every DB column without N+1 calls.

### Corporate group billing (live)

`group_billing` exposes `GET /api/group-bills?status=open|all`, `GET
/api/group-bills/:id`, `POST /api/group-bills`, `POST
/api/group-bills/:id/payments`, and `POST /api/group-bills/:id/void`. One `GBL_*`
sidecar identifies payer-owned AR while its linked `TXN_*` remains the
totals/payment/acknowledgement/day-summary/void/refund engine. Create accepts one
active Corporate payer and 2–20 distinct real patients with exact service
allocations. Shared Zod validation, clinical-order patient/service matching,
one-branch RLS, audit triggers, and persisted idempotency make the aggregate atomic
and retry-safe. Group transactions are excluded from patient AR and patient
tender/credit allocation; a DB trigger also forbids `Credit` and mismatched payment
payers. TenantAdmin, BranchAdmin, Cashier, and Branch may list/create/pay;
whole-group void/refund/payment correction requires TenantAdmin or BranchAdmin even
through generic transaction routes. Public contracts use display IDs. No
payer-facing portal or export is enabled.

### Runtime Review Center (included in integration candidate — 2026-08-23)

- `GET /api/review-center?date=YYYY-MM-DD&q=<optional patient search>` returns
  server-owned counts and row-level current-branch work for incomplete minor
  guardian records plus stale encounters, unsettled non-prepayment
  transactions, prior open drawers, and completed orders with no documenting
  actor. Calendar-invalid dates return `400 VALIDATION_ERROR`.
- Every timestamp is converted with `AT TIME ZONE 'Asia/Manila'` before the
  clinic-date comparison. PostgreSQL's UTC session date is not operational day
  truth.
- `PATCH /api/review-center/missing-guardians/:patientId` accepts all three
  guardian fields plus `expectedRowVersion`. It requires the patient to be an
  active, non-merged minor whose home branch matches the authenticated branch;
  cross-branch targets return 404 and stale reviews return 409.
- Router roles are `TenantAdmin`, `BranchAdmin`, `Physician`, `Nurse`, and the
  shared `Branch` account. A concrete branch assignment is mandatory; Cashier
  and platform principals are rejected.
- Reads and correction writes run inside `withTenantTx`; tenant/user/branch GUCs
  drive RLS and the database audit trigger. Only public display IDs cross the
  wire. AppSheet importer exceptions and migration-review queues are never
  queried.
- Prior open drawers link to `/branch/kiosk`. The canonical
  `GET /api/cash-drawer/current` owner endpoint returns the oldest open branch
  session even when it began on a prior day, so an accountable operator can
  close the exact exception before opening another shared branch drawer.
  Cash-drawer endpoints separately require `TenantAdmin`, `BranchAdmin`,
  `Cashier`, or `Branch`; clinical-only reviewers see the exception without a
  financial write affordance. A branch-wide partial unique index is the race
  backstop, while payments and deposits resolve the same deterministic Open
  session across Manila-day rollover.

Full predicates, UI behavior, exclusions, and next slices:
[`docs/specs/review-center-phase-1.md`](../specs/review-center-phase-1.md).

### Revenue-integrity reports (live, 2026-08-23)

`/api/reports` exposes bounded, typed endpoints for AR aging,
administered-but-unbilled work, payment reconciliation exceptions, branch/day
financial truth, and filter options. Tenant scope is admin-only;
Cashier/Branch remain branch-scoped; Nurse/Physician can read only the
unbilled worklist. Payer attribution comes from authoritative transaction
headers while payment-tender payer remains separately visible. Reconciliation
includes the imported `Mismatch` state. Day facts delegate to `day_summary`,
use Asia/Manila calendar boundaries, and name its Draft/Pending/Paid-inclusive
aggregate `transactionNetTotal` rather than implying accounting recognition.
`POST /api/reports/daily-revenue/export` generates the stable CSV on the
server, hashes it, durably writes an `EXPORT` audit row, and only then returns
the file payload; audit failure prevents delivery.

> **Bite-outcome migration note:** `record-outcome` also accepts `DiedUnknownCause`, used only when the source confirms death but records neither cause nor FAT result. It never cancels Day-28 PEP. `Pending` is not an outcome; it means no final observation has been recorded.

### Detail endpoint convention

Each `GET /:id` runs inside a `db.transaction` that sets RLS context, looks up the row by `(tenant_id, id)`, performs all relation joins in parallel via `Promise.all`, and returns 404 on miss. See `apps/backend/src/modules/transactions/db.ts` (`getTransaction`) for the canonical pattern with multiple parallel joins.

**Seed script**: `pnpm --filter @surevax/backend db:seed` (or `tsx src/shared/db/seed.ts`) populates ~250 rows across all 22 tables — 20 patients, 15 transactions (with line items + payments), 24 clinical orders, 11 consent records, 5 lab orders, 10 inventory lots, 4 payer profiles, 3 partner labs, 26 time logs, 8 approval requests, 22 audit entries, plus 29 patient tags. Idempotent via `onConflictDoNothing()`.

**Auth middleware** (`src/shared/middleware/auth.ts`) skips JWT check for `PUBLIC_PATHS` set (`/api/auth/login`, `/api/auth/logout`, `/api/auth/refresh`, `/health`). All other routes require a valid `access_token` HTTP-Only cookie. JWT verify errors are differentiated: `TokenExpiredError` → 401 `TOKEN_EXPIRED` (silent); other JWT errors → 401 `INVALID_TOKEN` + `logger.warn` with route + IP (forgery signal).

**Admin authorization**: every router under `/api/admin/*` is mounted with `requireRole('TenantAdmin','BranchAdmin')` from `src/shared/middleware/requireRole.ts` (some endpoints like `/api/admin/patients/.../cancel-pending-orders` and `/api/admin/dpa/purge` are `requireRole('TenantAdmin')` only). Non-admin authenticated users get 403 `FORBIDDEN`. The Branch-kiosk endpoints (`/api/branch/*`) mount with `requireRole('Branch','TenantAdmin','BranchAdmin','Nurse')` — Nurse is included so the standing-orders form can pull the physician list when a nurse is logged in directly.

> **TenantAdmin / SuperAdmin nomenclature**: Wave 2.2 (2026-05-18) renamed the canonical admin role from `SuperAdmin` to `TenantAdmin`; `SuperAdmin` remains in the `user_role` enum for back-compat with rows seeded before the rename. Backend `requireRole` calls are exact allow-lists (no implicit alias) and now say `TenantAdmin` everywhere in this doc: a route only accepts `SuperAdmin` if it is spelled out explicitly (e.g. `patient_accounts`'s in-handler `ADMIN_ROLES` set, and the frontend's `RequireAdminLayout`/`ADMIN_ROLES`, both intentionally accept both for back-compat). See `.claude/rules/gotchas.md` "SuperAdmin → TenantAdmin rename".

**Login gating** (`users.can_login`): `/api/auth/login` returns the same generic 401 (`AUTH_FAILED`) when the matched user has `can_login = false`. The check fires **after** bcrypt to preserve the timing-equalization guard. Only `TenantAdmin`/`BranchAdmin`/`Branch` rows default to `can_login=true`; Nurse/Cashier/Physician rows are directory entries (clock-in dropdown, "authorized by" picker) until an admin flips the toggle via `PATCH /api/admin/users/:id`.

**JWT**: `jsonwebtoken` — access token 15 min, refresh token 7 days, HS256 pinned on sign + verify. Both are HTTP-Only Secure cookies. Secrets (`JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`) are required ≥32 chars — backend exits at boot if unset or dev-marker. Login is timing-safe (dummy `bcrypt.compare` on the no-user branch). Login + refresh have a per-route 10/min limiter beyond the global 600/min (env-tunable `RATE_LIMIT_MAX`).

**Refresh-token rotation**: refresh tokens are persisted in `refresh_tokens` (`jti`, `family_id`, `expires_at`, `revoked_at`, `replaced_by_id`). Every `/api/auth/refresh` rotates: revoke old, issue new in same family. Reuse of a revoked `jti` revokes the entire family and 401s with `code: 'TOKEN_REUSED'` (catastrophic-loss defense). `/api/auth/logout` revokes the current row server-side.

**CSRF**: backend rejects state-changing requests (`POST/PUT/PATCH/DELETE`) that lack `X-Requested-With: fetch` (`src/shared/middleware/csrf.ts`, mounted between `cookieParser` and `authMiddleware`). The custom header forces CORS preflight, which the strict origin allow-list blocks from non-allowed origins. The frontend `apiFetch` pattern in every `features/*/api.ts` sends the header on every request (including the 401-then-refresh-retry path).

**Audit trigger**: `audit_log_changes()` (defined in `0002_audit_redaction.sql`) `RAISE EXCEPTION` if `app.current_tenant_id` GUC is unset on a tenant-scoped table (no silent fallback). It also strips a deny-list of PII/secret column names from the JSONB diff before insertion: `password_hash`, `allergies`, `conditions`, `contact_number`, `email`, `address`, `date_of_birth`, `guardian_*`, `insurance_*`, `api_key`, etc.

**Error handling**: 500 responses never include `detail: String(err)` unless `EXPOSE_ERRORS=1` is set (the env was decoupled from `NODE_ENV` because every deployed env runs `development`). Pino logger has `redact` configured for `req.headers.cookie`, `req.headers.authorization`, `req.body.password`, `*.passwordHash`, `res.headers["set-cookie"]`. Body limit explicitly `100kb`. `app.set('trust proxy', 1)` so per-IP rate-limiting works behind Railway's proxy.

**Patients list**: cursor-based pagination (`createdAt` DESC), max 100 per page, supports `?q=` for `ilike` search on lastName/firstName/contactNumber.

**Patient onboarding channel** (2026-06-01, migration `0008`): `POST`/`PATCH /api/patients` accept `onboardingChannel` (Zod `z.enum` — `Walk-in | Referral | Vaccination drive | Partner | HMO | Social media | Returning patient | Other`) and `onboardingChannelPayerId` (a `PYR_` payer display id, only for Partner/HMO). `createPatient`/`updatePatient` resolve the display id → bigint FK; `GET /api/patients/:id` returns the resolved `onboardingChannelPayer: { id, name } | null` instead of the raw bigint. The allowed-value list is duplicated inline in the route (per the `@surevax/shared` runtime-import constraint) and mirrored in the frontend `ONBOARDING_CHANNELS`.

### Phase-1 financial route contract (PR #617)

All HTTP-facing money services require a typed caller context derived from the
authenticated request. Internal callers do not gain an omission-based bypass;
they must explicitly pass `{ kind: 'internal' }`. Runtime omission fails closed
with `MONEY_CALLER_CONTEXT_REQUIRED`.

| Route                                                           | Required identity/attribution behavior                                                                                                     |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /api/transactions` with inline payment(s)                 | Route supplies authenticated role/display ID. Shared `Branch` login requires named staff + PIN; receiver is persisted on each payment leg. |
| `POST /api/transactions/:id/payments`                           | Same fail-closed caller and receiver rule.                                                                                                 |
| `POST /api/transactions/:id/payments/:paymentId/correct-method` | Correction actor is authenticated/attested, but the replacement payment retains the original receiver; actor is separately audited.        |
| `POST /api/patients/:id/payments`                               | Caller identity is threaded into every oldest-first allocated payment leg.                                                                 |

Other financial contract guarantees:

- The shared create schema and backend service reject blank/missing OSCA/PWD
  `discount.idNumber` before any write.
- An already-claimed clinical order returns deterministic
  `409 CLINICAL_ORDER_ALREADY_BILLED`, including the database race-time path.
- Payment `receivedById` is a public `USR_…` display ID, not an internal bigint.
- A legacy payment with no receiver returns `409 PAYMENT_RECEIVER_UNKNOWN` and
  remains uncorrected until an evidence-backed TenantAdmin repair.
- HTTP money-route additions must supply the caller context and extend route
  attribution, shared-kiosk attestation, and authorization tests.

## Authentication (MANDATORY Cookie Flow)

| Rule                 | Detail                                                                                                                                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Access token**     | Short-lived — **default ~15 min**                                                                                                                                                                                                  |
| **Refresh token**    | Long-lived — **default ~7 d**; **persisted in DB** (hashed / revocable row)                                                                                                                                                        |
| **Access delivery**  | **`Set-Cookie`**: **HTTP-Only**, **`Secure: true` unconditionally**, **`SameSite=None`** (Cloudflare Pages and Railway are different eTLD+1s — cross-site cookies required) — **NEVER `localStorage` / `sessionStorage` for JWTs** |
| **Refresh delivery** | **Separate** **HTTP-Only**, **Secure** cookie — **NOT** readable by JS                                                                                                                                                             |
| **Login**            | Validate credentials (**bcrypt**) → issue **access** + **refresh** → set cookies                                                                                                                                                   |
| **401 handling**     | Client calls **`POST /auth/refresh`** → validate refresh (cookie + DB) → rotate/issue new **access** (and optionally **refresh**)                                                                                                  |
| **Logout**           | **Invalidate refresh** in DB + **clear cookies**                                                                                                                                                                                   |
| **Why**              | **`localStorage` JWTs** = **XSS-exfiltration** risk; **HTTP-Only** = **no JS access**                                                                                                                                              |

**Forbidden**: SPA pattern of **Bearer token in `Authorization` from `localStorage`** for this product’s web client.

## Tenant Middleware & RLS

| Phase       | Behavior                                            |
| ----------- | --------------------------------------------------- |
| **Phase 1** | **Hardcoded** `tenantId` (single clinic)            |
| **Phase 2** | Resolve from **JWT claims** or **subdomain** (etc.) |

**Middleware contract**: resolve tenant/user/branch identity and attach it to `req`, but **do not** execute `SET LOCAL` on a pooled connection in middleware.

```typescript
// Phase 2 dynamic resolution: JWT claim → X-Tenant-Slug header (or subdomain)
// → X-Dev-Tenant-Id (dev only) → 400 TENANT_REQUIRED. No silent fallback.
// See apps/backend/src/shared/middleware/tenant.ts for the canonical chain.
const tenantId = req.user?.tenantId ?? (await resolveTenantBySlug(slug))
const userId = req.user?.id
const branchId = req.user?.branchId ?? null
req.tenant = { id: tenantId, userId, branchId }
```

| Rule                                  | Detail                                                                                                                                                                         |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **RLS**                               | **Primary** tenant isolation — **not** app-only `WHERE tenant_id = …` as **sole** defense                                                                                      |
| **RLS context scope (MANDATORY)**     | **`SET LOCAL` MUST ONLY be executed inside a `db.transaction()` block at the service layer. Never execute `SET LOCAL` globally in Express middleware on a pooled connection.** |
| **Audit trigger context (MANDATORY)** | In that transaction, set all three session vars: `app.current_tenant_id`, `app.current_user_id`, `app.current_branch_id` so PostgreSQL audit triggers capture actor context.   |
| **Every request**                     | Tenant-scoped queries must run inside a transaction that sets RLS/audit context before reading or writing tenant data.                                                         |
| **SQL injection**                     | **Never** string-interpolate raw IDs into SQL for `SET` — use **parameterized** `set_config` / bound params.                                                                   |

**Service-layer transaction pattern (required for tenant-scoped DB access):**

```typescript
await db.transaction(async (tx) => {
  await tx.execute(sql`select set_config('app.current_tenant_id', ${tenantId}, true)`)
  await tx.execute(sql`select set_config('app.current_user_id', ${userId}, true)`)
  await tx.execute(sql`select set_config('app.current_branch_id', ${branchId}, true)`)

  // All tenant-scoped reads/writes happen through `tx` in this callback.
  // ...queries...
})
```

## Backend Invariants

- **Express.js** — **not NestJS**.
- **Drizzle ORM** — **not Prisma / TypeORM**.
- **Auth**: **HTTP-Only + Secure cookies** for **access** and **refresh**; **refresh** stored **server-side** (DB).
- **NO `localStorage` / `sessionStorage` JWTs** for session — **non-negotiable** for the web client.
- **Zod** at the edge; **shared** schemas with the frontend.
- **Pino** for logs — **not** unstructured console logging in production paths.
- **Sentry** or **GlitchTip** for production error tracking.
- **Feature modules** — **not** MVC-by-default layout.
- **Tenant middleware** resolves tenant/user/branch context only; it does **not** run `SET LOCAL` on pooled connections.
- **RLS context** (`SET LOCAL` / `set_config(..., true)`) is set **only inside `db.transaction()`** and includes `app.current_tenant_id`, `app.current_user_id`, `app.current_branch_id`.
- **Helmet → CORS → rate limit → auth → tenant → validate** — preserve ordering discipline.
- **Mutations**: **transactions** + **audit** on writes.
