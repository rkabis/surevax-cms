# Pilot Integration — run + land an /orchestrate-pilot wave

The `orchestrate-pilot` workflow (`.claude/workflows/orchestrate-pilot.js`)
implements and adversarially verifies units, returning patches. This skill
covers everything the workflow itself can't: correct invocation, patch
recovery, integration, and verification. Lessons baked in from the 2026-06-12
first run (PR #557) and the 2026-06-13 contract-codegen 3-wave fan-out.

## Model tiers (pinned in the workflow — don't override)

- Coordinator (you): session model (Fable/Opus) — wave design, verdict
  reading, integration.
- Impl agents: `sonnet`. Verify agents: `opus`.

## 1. Invocation — structured args or silent no-op

```js
Workflow({
  name: 'orchestrate-pilot',
  args: {
    baseRef: 'main',
    units: [{ id: 'U1', title: '…', instructions: '…', allowedFiles: ['apps/…/x.ts'] }],
  },
})
```

- **A prose string arg silently yields "0 units"** and exits in ~10ms. Pass a
  real JSON object.
- Scout the wave inline FIRST: enumerate exact `allowedFiles` per unit before
  dispatch. Workers fork from **main HEAD**, not the coordinator branch —
  land spine prereqs to main first.
- Units >500 LoC stall; split. Diffs <100 LoC don't justify a worker — do
  them inline.

## 2. Verify prompt needs wave design facts — copy the script

The stock verify prompt knows the five repo bug classes but NOT this wave's
intentional conventions. Waves 1–2 of the codegen fan-out went 0/6 "passed"
purely because verifiers flagged coordinator-owned-by-design gaps (missing
`.gen.ts`, untouched registry).

Every Workflow invocation persists its script and returns the path. To extend:
copy/edit that file and re-invoke with `{scriptPath}`, adding to the verify
prompt:

```
WAVE-SPECIFIC DESIGN FACTS (do NOT report these as findings):
- <generated files are regenerated by the coordinator after integration>
- <registry/index wiring is coordinator-owned>
- …
```

## 3. Patch recovery — transport is lossy in two ways

1. **Blocked units drop their patch** from the result (only
   `{unit, reason, findings}` returns). Recover from the workflow transcript
   dir: `grep -l 'UNIT <id>' <transcript-dir>/agent-*.jsonl`, then walk the
   JSON events for the `StructuredOutput` tool_use and extract its `patch`
   input.
2. **Patches in the result JSON are HTML-entity-escaped** (`=&gt;`,
   `&amp;&amp;`) — `python3 -c 'import html,sys; print(html.unescape(sys.stdin.read()))'`
   before `git apply`. Transcript-recovered patches are clean.

Write every per-unit patch to `/tmp/<wave>/<unit>.patch` BEFORE applying
anything — don't re-parse the result JSON twice.

## 4. Applying — the git-apply ladder

Model-generated diffs often carry wrong hunk line-counts. Per patch:

```bash
git apply /tmp/w/<unit>.patch \
  || git apply --recount /tmp/w/<unit>.patch \
  || git apply --recount --reject /tmp/w/<unit>.patch  # then hand-apply *.rej
```

Whole-file-rewrite hunks that still fail are faster to redo by hand from the
patch's post-image than to massage.

## 5. Blocked ≠ worthless — fix forward

Even fully "blocked" waves were ~90% usable. Apply blocked patches too, then
use the verify `findings` as a punch list and fix inline. Findings have been
high-quality (real `satisfies` failures, dead endpoints, phantom fields).
Re-running units costs more than fixing forward.

## 6. Main-tree write check (Workflow-from-worktree gotcha)

File-mutating workflow agents launched from a worktree can land edits in the
**main repo tree**. After every file-mutating run:

```bash
git -C "$(git rev-parse --path-format=absolute --git-common-dir)/.." status --short
git status --short   # the worktree
```

If edits landed in main: `cp` them into the worktree, then
`git -C <main> restore <files>`. Never commit to main directly.

## 7. Integration tail — the workflow agents don't build/test

```bash
git checkout -b integration/<wave>
# apply passing patches (ladder above), commit per unit
pnpm gen:contracts          # if any contract.ts changed
pnpm agent:check            # format, lint, typecheck, build, bare-write gate
# curl smoke against the seeded dev stack — see the curl-smoke skill.
# REQUIRED: diff-only verify cannot catch runtime SQL bugs (the Drizzle
# unqualified-correlation bug on PR #557 passed verify, failed the smoke).
pnpm prettier --write . && pnpm format:check
# ship ONE PR for the whole wave
```
