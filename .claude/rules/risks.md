3. **Testing strategy — backend strong, frontend layers now in place, depth still growing.** Backend: 238 `it()` blocks across 32 integration files (RLS, audit trigger, CSRF, FEFO, transactions, idempotency, tenant resolution, auth, money) on Vitest 4 (projects API). Frontend component layer (H11): Vitest + Testing Library + MSW scaffold with a handful of specs. **Browser E2E now exists** (added 2026-06-04): Playwright suite under [`e2e/`](../../e2e) driving real Chromium against the full seeded stack — auth (Branch→kiosk, admin, invalid creds, redirect), the daily loop (administer a scheduled dose → payment hand-off), end-of-day reconciliation (`day-summary.spec.ts`, added 2026-07-06 — the `/day-summary` report renders all five blocks → "Close day" snapshot), the Arrivals registration wizard, the cashier transaction-create, and authenticated page smoke. Runs as the `Branch` operator persona; gated in CI by the `e2e` job. `pnpm test:e2e` locally (needs `pnpm dev` up, or it boots the stack). This suite caught **three** backend bugs, all fixed in the same change: (1) the `maintain_lot_balances` trigger broke **every** inventory deduction (see [`patterns.md`](patterns.md) negative-inventory section); (2) `/api/arrivals/atomic` resolved patient/provider with bare `db` reads outside `withTenantTx` → zero rows under FORCE RLS → 404 on every commit; (3) the arrivals preview-bundle lot lookup ignored the `service_eligible_products` junction. A fourth (`/api/dose-calc` rejecting `SVC_ERIG_INF` despite `requiresDoseCalculation=true`) was flagged here and later **fixed 2026-06-14**: `resolveDoseRule` accepts the catalog id or the bare code, so ERIG/HRIG/HTIG/ATS are administrable through the UI again. Still thin: one happy-path spec per flow; `daily-loop.spec.ts` now drives the clinic's highest-leverage workflow end to end — a bite walk-in registered onto a rabies PEP course (WHO Cat II, IM 5-dose, physician-on-duty noted), Day-0 anti-rabies dose administered, payment collected to Paid — staying deterministic on any date by registering its own fresh Day-0 order and opening it via the `?selected=` deep link; no coverage thresholds. Hardening the suite (2026-07-06) also fixed a real flakiness class the shared-IP serial run exposed: the `AuthProvider` `/api/auth/me` bootstrap treated any non-OK response as "logged out", so a transient `429` (the old `100/min` global rate limiter, tripped by request bursts) or a merely-expired access token bounced valid sessions to `/login`. The bootstrap is now refresh-aware (`401` → shared single-flight refresh → retry) and transient-tolerant (`429`/`5xx` → backoff + retry, no spurious logout), and the global limiter is now `600/min` (env-tunable `RATE_LIMIT_MAX`), sized for a multi-staff clinic behind one NAT IP; the `10/min` credential limiter is unchanged.
4. **AppSheet migration plan — started, PEP/PrEP doses scoped.** Field mapping + data quality for most entities still undefined, but the hardest piece — reconstructing every patient's PEP/PrEP rabies **dose schedule** from the wonky legacy `Immunization` sheet — now has a locked deterministic approach + committed source ([`scripts/migration/reconstruct_pep_doses.py`](../../scripts/migration/reconstruct_pep_doses.py), [`docs/migration/pep-prep-dose-reconstruction.md`](../../docs/migration/pep-prep-dose-reconstruction.md)): episode segmentation, an empirically-validated regimen catalog, **dose-sequence-number keying** (not nearest-date), and a fill/flag taxonomy. 39,372 dose-rows auto-resolve; 2,824 flagged for manual review; deferred clinical questions (A2 4→5 dose transition, Q4/Q5/Q8/Q11) still gate full closure. Other entities (patients, transactions, inventory, non-rabies vaccines) not yet started.
